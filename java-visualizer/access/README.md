# הכניסה המשותפת (dsviz-access.jar)

קוד אחד לכניסה (מורה / תלמיד / עמדת מחשב) לכל התוכנות במחשב: Eclipse, IntelliJ, Visual Studio (המאגר וסרגל הכלים),
VS Code ו"מודלים חישוביים". מי שנכנס באחת — מחובר בכולן, והתנתקות באחת מנתקת בכולן, מיד.

```
sh tools/build-access.sh        → build/access/dsviz-access.jar   (Java 8, רק מודולים שב-Java של ההתקנה)
```

| קובץ | מה |
|---|---|
| `Account.java` | כניסה עם Google בדפדפן (loopback + PKCE דרך `/signin` של השרת), חיבור עמדה, בדיקה מול השרת, התנתקות, השמירה המוצפנת |
| `AccessGate.java` | מסך הכניסה (Swing) ו-`onChange` (בחוט של Swing) |
| `AccessWatch.java` | שינויים מתוכנה אחרת: `AccessWatch.listen(r)` — WatchService על התיקיות + בדיקה קלה כל ‎1.5‎ שניות |
| `OsTrust.java` | תעודות ממאגר מערכת ההפעלה (סינון אינטרנט שבודק תעבורה מוצפנת) |
| `Json.java` | JSON קטן (משמש גם קוד אחר) |

החבילה נשארה `il.lamerhav.dsviz` — מי שמשתמש בה לא השתנה. ה-jar נכנס כמו שהוא (המחלקות שלו מחולצות) ל:
`dsviz.jar` (tools/build-lib.sh), התוסף של Eclipse (tools/build-all.sh), `dsviz-bank-vs.jar` (tools/build-bank-vs.sh),
התוסף של IntelliJ (`implementation(files(...))` ב-intellij-plugin/build.gradle.kts → `lib/dsviz-access.jar`).

## איפה נשמרת הכניסה (מקום אחד לכל התוכנות, נסתר)

| | Windows | Mac | Linux |
|---|---|---|---|
| המשתמש (`a.dat` מורה / תלמיד, `o.dat` התנתקויות בלי אינטרנט, `i.dat`, `teacher.flag`, `.lock`) | `%LOCALAPPDATA%\Lamerhav\.cache` | `~/.local/share/.lamerhav` | `~/.local/share/.lamerhav` |
| גיבוי | `%APPDATA%\Lamerhav\.cache` | `~/.config/.lamerhav` | `~/.config/.lamerhav` |
| כל המחשב (`s.dat` עמדה, `i.dat`) | `%ProgramData%\Lamerhav\.cache` | `/Users/Shared/.lamerhav` | (אצל המשתמש) |

- הקבצים מוצפנים (AES-GCM, מפתח לפי המחשב) ומסומנים כנסתרים ב-Windows. האישור בתוכם חתום בשרת (RSA) ונבדק בכל קריאה.

### "קובץ הזהב" — נשארים מחוברים, תמיד

`a.dat` (מורה / תלמיד) ו-`s.dat` (עמדה) הם "קובצי הזהב": מקום אחד קבוע לכל תפקיד, שאף התקנה / עדכון (`/S /UPDATE`, `install.sh`) /
התקנה מחדש / הסרה לא נוגעים בו (‎`%LOCALAPPDATA%\DSViz`‎ היא תיקיית ההתקנה, ו-‎`~/Library/Application Support/DSViz`‎ מוחלפת כולה
בכל עדכון ב-Mac — לכן הקבצים לא שם). הסרה מלאה משאירה אותם בכוונה.

| | |
|---|---|
| כתיבה | אטומית: קובץ זמני ייחודי + החלפה בשינוי שם, בתוך הנעילה |
| גיבויים | `<קובץ>.bak` באותה תיקייה (גם לעמדה ב-ProgramData — לכל המשתמשים) + עותק בתיקיית הגיבוי. קובץ ראשי חסר / פגום / חתוך — נקרא מהגיבוי ומשוחזר; הפגום נשמר בצד כ-`.bad` |
| מזהה ההתקנה | גם בתוך הקובץ (השדה `id`, אותו תוכן כמו `i.dat`): `i.dat` שנמחק בכל המקומות — הכניסה עדיין נפתחת. קובץ שהועתק למחשב אחר — עדיין לא |
| העברה מהמקום הישן | `~/.dsviz/account.json`, `ProgramData\DSViz\station.json` → קובץ הזהב, פעם אחת. ישן שלא נפתח — נשאר כמו שהוא; ישן שנבדק מאוחר יותר — נבחר; אחרי שקובץ הזהב נפתח, הישן מקבל שם `.migrated` (לא נמחק, ולא "חוזר לחיים" אחרי התנתקות; כשאי אפשר לשנות את שמו — נרשם ב-`m.dat`) |
| נמחק רק כש | מורה / תלמיד לוחצים "התנתקות"; עמדה — רק כשהשרת עונה `revoked` (המורה / ההנהלה שחררו; כל קובצי העמדה של אותה עמדה). למורה / תלמיד גם `revoked` / `invalid` / `not-teacher` מהשרת (התנתקות ממקום אחר, ההנהלה) |
| לא נמחק אף פעם על | בלי אינטרנט, 429 / 500 / 404, סינון / פורטל (תשובה לא תקינה), אישור מזויף; לעמדה גם `invalid` (עם סיבה או בלי — הכרטיס הוחלף בחיבור חוזר; שחרור אמיתי מגיע כ-`revoked`) |
| אישור שפג (בלי אינטרנט זמן רב) | מסך הכניסה קודם בודק מול השרת עם הכרטיס השמור (`hasSavedToken` → `refresh`), ופותח בלי לבקש קוד מחדש |
| התנתקות | רק למורה / תלמיד שנכנסו עם Google (`AccessGate.canSignOut`). בעמדה אין התנתקות בשום מקום (המאגר ב-Eclipse / IntelliJ / Visual Studio, "מודלים חישוביים"); מורה שנכנס מעל עמדה מתנתק רק מהחשבון שלו |

בדיקות: `Golden` (בסידור התיקיות של Windows ושל Mac, ב-Linux) — ב-`tools/test/access/run.sh`.
- `teacher.flag` — לא סוד (מייל ושם): סרגל הכלים של Visual Studio (C#) מציג לפיו את "עמדת ניהול". עד גרסה 1.0.1 הוא היה
  ב-`%LOCALAPPDATA%\DSViz\teacher.flag`; Java מוחקת את הישן, והסרגל קורא גם ממנו (לגרסה אחת) ועוקב אחרי שתי התיקיות.

## עמדת מחשב שלא "משתחררת לבד"

מחשב מחובר ביקש שוב קוד בכל פעם שאחד מאלה קרה. כולם טופלו (בדיקות: `StationKeep`, ובשרת `test/access-test.mjs`):

| מה קרה | התיקון |
|---|---|
| **מזהה המחשב השתנה.** הוא `hash(מזהה Windows + מזהה אקראי מ-i.dat)`, וממנו נגזרים המפתח של הקבצים וה-`mid` שבאישור. `reg.exe` חסום לתלמידים (מדיניות "כלי עריכת הרישום") או נכשל רגעית → נלקח מזהה חלופי מקובץ, אחר לגמרי. Java של 32 ביט רואה רישום אחר מ-Java של 64 ביט. ב-Mac שם המחשב משתנה לפי הרשת, והמזהה האקראי נוצר מחדש | מזהה Windows נקרא בשלוש דרכים (`reg /reg:64`, `reg`, PowerShell), ונשמר ב-`i.dat` (שורה 3: `g:<אמיתי>` / `f:<חלופי>`). כשאי אפשר לקרוא — משתמשים בשמור. כשכבר יש קובץ שמור של עמדה / משתמש, נבחר המזהה שפותח אותו, כך שעדכון גרסה לא מנתק מחשב מחובר. ב-Mac / Linux שם המחשב לא נבדק. קובץ שהועתק ממחשב אחר עדיין נדחה (שם מחשב אחר, או מזהה Windows אחר מהשמור) |
| **נבחר קובץ העמדה הלא נכון.** `stationFile()` לקח תמיד את הקובץ המשותף (ProgramData) אם הוא קיים — גם כשהוא לא נפתח או ישן. חיבור חדש שנשמר אצל המשתמש "נעלם", ו-`migrate` אף מחק חיבור חדש כשכבר היה קובץ ישן | נבחר הקובץ שנפתח ושהאישור בו תקף (מבין שניים — זה שנבדק אחרון). חיבור נשמר במקום הראשון שנכתב ונקרא בחזרה עם הכרטיס החדש. קובץ ראשי שלא נפתח נקרא מהגיבוי |
| **משתמש Windows אחר לא יכול להחליף את הקובץ המשותף** (הרשאות ברירת המחדל של ProgramData: קריאה בלבד לקבצים של אחרים) | מי שיוצר את `%ProgramData%\Lamerhav` נותן לקבוצה "משתמשים" הרשאת שינוי (`icacls`, לפי SID), פעם אחת |
| **השרת החליף את הכרטיס של העמדה בכל חיבור חוזר** — משתמש אחר / תוכנה אחרת באותו מחשב שהתחברו שוב ניתקו את הקודם, וחוזר חלילה | העמדה מחזיקה את 8 הכרטיסים ו-8 מזהי המחשב האחרונים; כולם תקפים עד שהמורה / ההנהלה משחררים. התוכנה לא מוחקת עמדה על "לא תקף" — משרת ישן (בלי `why`) או חדש (גם עם `why`); רק על `revoked` (שוחררה) |
| **מחשב ששוחזר / קובץ שנמחק קיבל מזהה חדש ולקח עוד מקום מהמורה** | בחיבור נשלח גם `stable` = `hash(מזהה Windows + שם המחשב)`, בלי החלק האקראי. השרת מזהה לפיו שזה אותו מחשב, ומחזיר את אותה עמדה |

**לראות למה מחשב ביקש קוד מחדש:** ביומן של ההנהלה, `station.again` כולל את הסיבה שהתוכנה שלחה (`why`: אין קובץ / הקובץ לא נפתח / האישור לא אומת / השרת דחה / העמדה שוחררה), ו-`station.rejected` נרשם כשהשרת דוחה כרטיס של עמדה קיימת (פעם ביום לכל עמדה וסיבה).

## כמה תוכנות בבת אחת

- **נעילה**: כל כתיבה / מחיקה עוברת ב-`Account.locked` — `synchronized` בתוך התהליך ו-`FileLock` על `.lock` בתיקיית
  המשתמש בין התהליכים (עד 5 שניות; בלי הרשאה / תוכנה תקועה — כותבים בלי נעילה, כמו קודם). קובץ זמני ייחודי לכל כתיבה,
  והחלפה אטומית (move) — קורא אף פעם לא רואה חצי קובץ. המזהה `i.dat` נוצר בתוך הנעילה (שתי תוכנות שעולות יחד בפעם הראשונה
  לא יוצרות שני מזהים).
- **בדיקה מול השרת** (`refresh`) שומרת רק אם בקובץ עדיין אותו כרטיס (`storeIfSame` / `forgetIfSame`) — בדיקה ארוכה בתוכנה
  אחת לא מחזירה כניסה שתוכנה אחרת ניתקה בינתיים.
- **שינויים**: `AccessWatch` מודיע רק כשמי שמחובר באמת השתנה (`Account.fingerprint` — סוג, מייל, שם, תוקף, מצב; בלי הכרטיס),
  לא על כל שמירה מחדש. `AccessGate.onChange` מפעיל אותו לבד (Eclipse: הכפתור "עמדת ניהול" מתעדכן מיד גם כשהכניסה /
  ההתנתקות נעשו ב-Visual Studio).

## תלמיד: הרשמה, עצמאי / מורה, ותשלום (מוכן למעבר לתשלום)

- **הרשמה, פעם אחת:** אחרי "כניסה עם Google" הדף `/signin` מבקש שם מלא וטלפון נייד, ובפעם הראשונה גם "תלמיד עצמאי" / "יש לי
  קוד מורה" (`worker/public/register.js`) — ורק אחר כך חוזר לתוכנה. השרת שומר `students/{email}.fullName / phone / registeredAt`;
  המורה רואה את השם המלא. עדכון — בדף "החשבון שלי".
- **`caps`:** התוסף שולח `caps: ["register"]` בכניסה ובכל בדיקה. תלמיד שעוד לא נרשם מקבל `register` (בלי אישור — המאגר סגור)
  והכרטיס נשמר; לקוח ישן (בלי caps) מקבל `ok` כמו קודם. `Account.studentInfo()` — מה שהשרת אמר (רשום, עצמאי / מורה, מחיר).
- **בחינם עכשיו, בתשלום כשמחליטים:** מתג אחד במסוף ההנהלה ("תלמידים בחינם"). כשמכבים — גם תלמיד רשום שכבר מחובר מקבל `pay`
  בבדיקה הבאה. במקום "הכניסה לא בתוקף" חלון הכניסה מציג "המאגר פתוח עכשיו בתשלום" (או "נשאר להשלים הרשמה") עם כפתור לדף
  (`Account.studentPageUrl` — עם `u=` סימן של החשבון, בלי המייל), ובודק מול השרת עד שהמאגר נפתח. בלי כניסה מחדש.

- **"המורה שלי" — בתוך התוכנה** (`AccessGate.showMyTeacher`, `Account.studentJoin / studentLeave`): תלמיד מחובר מקליד את קוד
  המורה, מחליף מורה (עם אישור) או יוצא — בלי הדפדפן. הקישור במאגר: "הצטרפות למורה" / "המורה שלי" (`AccessGate.teacherLink()`;
  ריק כשהשרת לא יודע לקבל הגשות). בחלון השאלה, תלמיד בלי מורה רואה במקום הכפתור "רוצים להגיש למורה? מצטרפים עם קוד המורה",
  ואחרי ההצטרפות הכפתור "הגשה למורה" מופיע מיד (`AccessGate.onChange` / `offChange`).
- **מורה — "עמדת ניהול" בתוכנה:** הקוד (לתלמידים ולמחשבי המעבדה), העמדות, ו"N הגשות חדשות מחכות לך"
  (`Account.teacherSummary` → `POST /v1/teacher/summary`, רק כשהשרת שולח `features: ["summary"]`).

## "הגשה למורה" (Submit, RunCheck)

- **מי מגיש:** תלמיד שמשויך למורה (בשם עצמו) או עמדת מחשב של הכיתה (בשם העמדה, עם "שם המגיש" חובה — ריק בכל הגשה). מורה /
  תלמיד עצמאי — אין כפתור. למי ההגשה מגיעה קובע השרת, לפי הכרטיס.
- **רק כשהשרת יודע:** בכל תשובה השרת שולח `features: ["submit"]`, והוא נשמר עם הכניסה (`Account.serverHas`). מול שרת ישן — אין כפתור.
- **בדיקת ההרצה** (`eclipse-plugin/.../RunCheck.java`), במחשב של התלמיד: קומפילציה (ecj / javac / dsviz-cs), הרצה עד 10 שניות,
  פלט עד 2,000 תווים מול הפלט הרצוי של השאלה; תוכנית שקוראת מהמקלדת — לא מורצת. קוד שלא מתקמפל: **לתלמיד מוצג רק כמה
  שגיאות יש** ("יש בו 3 שגיאות" — `Result.errorCount`), בלי הרשימה; למורה נשלחות עד 6 הראשונות עם הסבר בעברית, והמספר הכולל.
- **בלי אינטרנט:** ההגשה נשמרת בתיבת יוצא ליד קובצי הכניסה (`submits/`) ונשלחת בפעם הבאה — רק בשם מי שהגיש אותה.
- **בחלון "השאלה"** (Eclipse — `BankFloat`; Visual Studio / VS Code / IntelliJ — `BankVsFloat`): "הגשה למורה <שם>", דף ההגשה במקום
  השאלה, "הוגש למורה ב-10:42"; "סיימתי את התרגיל" מגיש לפני המחיקה ("לסיים בלי להגיש" — אם ההגשה לא עוברת).
  לתלמיד מחובר ההגשה נרשמת גם במחשב (`BankProgress.submitted`): בפעם הבאה שפותחים את השאלה כתוב "הוגש למורה <שם> ב-18.11, 10:42"
  (לא בעמדת מחשב — כמה תלמידים עובדים עליה).

## מול השרת: איזו תוכנה

`/v1/auth/redeem` ו-`/v1/station/claim` מקבלים שדה לא חובה `app` (`dsviz` / `automata`; `Account.app`, ברירת מחדל `dsviz`,
"מודלים חישוביים" — `automata`). הוא נרשם ביומן הפעילות (`app=automata`); ערך לא מוכר / לקוח ישן — בלי שינוי.
באישור החתום יש `apps` (בינתיים תמיד `["dsviz","automata"]`); `Account.Access.apps` / `opens(app)` — אישור ישן בלי השדה פותח בשתיהן.

## "מודלים חישוביים": התוכנה המקומית והממשק לדף

`automata-launcher/` (`il.lamerhav.dsviz.AutomataLauncher`, `tools/build-automata.sh` → `build/automata/dsviz-automata.jar`
עם dsviz-access בפנים, ו-`build/automata/app`). בהתקנה: `<התקנה>\automata\` ; הקיצור "מודלים חישוביים" מריץ
`javaw -cp "automata\dsviz-automata.jar;dsviz.jar" il.lamerhav.dsviz.AutomataLauncher`.

- שרת על `127.0.0.1` בלבד. הפורט נבחר באקראי בפעם הראשונה ונשמר (`%LOCALAPPDATA%\DSViz\automata-data\port`) — כדי שהשמירה
  של הדף (localStorage: העבודה, ההעדפות, ההתקדמות במאגר) לא תאבד בכל הפעלה; תפוס — פורט אחר.
- מפתח אקראי לכל הפעלה (`X-DSViz-Token`). הוא לא בשורת הפקודה: החלון נפתח עם קוד חד-פעמי (`/launch?c=…`, דקה אחת,
  פעם אחת) שמחזיר 302 ל-`/#dsviz-token=<מפתח>`; `access-client.js` שומר אותו ב-sessionStorage ומוחק אותו מהכתובת.
- Windows: Edge `--app=<כתובת>` עם פרופיל משלו (`%LOCALAPPDATA%\DSViz\automata-data\edge`); בלי Edge — הדפדפן הרגיל.
  Mac: הדפדפן הרגיל (`open`). הפעלה שנייה (עוד לחיצה על הקיצור) — לא שרת שני: קוד פתיחה מהשרת שרץ ועוד חלון.
- יציאה: כשאין דף פתוח — זרם האירועים נסגר ואין פנייה ‎30‎ שניות (בהתחלה — עד ‎2‎ דקות לחלון לעלות).
- בדיקות אבטחה בכל בקשה: `Host` = ‏`127.0.0.1:<port>` / `localhost:<port>` (נגד DNS rebinding); `Origin` (אם נשלח) — רק
  השרת עצמו; `Sec-Fetch-Site` (אם נשלח) — `same-origin` / `none`; `/api/*` — רק עם המפתח (השוואה בזמן קבוע), POST — רק
  `application/json`. קבצים — רק מתוך תיקיית האפליקציה. אף תשובה לא כוללת כרטיס, אישור או סוד.

| | בקשה | תשובה |
|---|---|---|
| מי מחובר | `GET /api/access` | `{state: "signed-out"/"teacher"/"student"/"station"/"pending"/"blocked", name, email, role, apps, offline, until, teacher, signing, canSignOut}` |
| כניסה עם Google | `POST /api/signin {role: "teacher"/"student"}` | `{ok, status: "waiting"}` מיד; בסוף — אירוע `signin` `{ok, status, message}` |
| ביטול כניסה | `POST /api/signin-cancel` | `{ok}` |
| עמדת מחשב | `POST /api/station {code, name}` | `{ok, status: "ok"/"bad-code"/"full"/"blocked"/"offline"/…, message}` |
| התנתקות | `POST /api/signout` | `{ok, status, message}`; עמדה — `{ok: false, status: "station"}` (רק המורה משחרר) |
| עמדת הניהול | `POST /api/teacher-panel` | `{ok}` (פותח את החלון של DSViz) / `{ok: false, status: "not-teacher"}` |
| אירועים | `GET /api/events` (SSE) | `event: access` (מיד, ובכל שינוי — גם מ-Eclipse / Visual Studio), `event: signin` |

`pending` — כניסה שמחכה לדפדפן, או תלמיד שעוד לא שילם; `blocked` — הגישה הושבתה.

בדף: `automata/app/js/access-client.js` (ES module) — `DSVizAccess.available()`, `get()`, `signIn(role)` (מחזיר את התוצאה
בסוף הכניסה), `cancelSignIn()`, `claimStation(code, name)`, `signOut()`, `openTeacherPanel()`, `onChange(cb)` (מחזיר פונקציה
להפסקה). התוכנה מוסיפה אותו לבד ל-index.html שהיא מגישה (הוא מחזיק את זרם האירועים — כך היא יודעת שהחלון פתוח); בלי
התוכנה (קובץ / אתר) — `available()` הוא false ו-`get()` מחזיר `{state: "unavailable"}`. אם באפליקציה אין את הקובץ — מוגש העותק
שבתוך ה-jar.

בדיקות: `AutomataIt` ב-`npm run test:access-java` (אבטחה, הממשק, כניסה / התנתקות / עמדה משותפות, הפעלה שנייה, יציאה כשאין
דף; `AUTOMATA_APP=<תיקייה>` — עם האפליקציה האמיתית).
