# מאגר התרגילים

כל שאלה היא קובץ JSON בתיקייה של הנושא שלה (`loops/`, `arrays/`, `strings/`, `classes/`, `recursion/`, `stack/`, `queue/`, `list/`, `tree/`).
לפני שהיא נכנסת לתוסף היא נבדקת: `sh tools/test/bank-check.sh`.

## רמות קושי

| רמה | מה זה | דוגמאות |
|---|---|---|
| **קל** (`easy`) | מעבר אחד על המבנה, ספירה / סכום / מינימום / חיפוש, בלי ליצור מבנה חדש | הערך הקטן ביותר במערך; כמה חוליות גדולות מ-x; סכום מחסנית (והיא חוזרת להיות כמו בהתחלה) |
| **בינוני** (`medium`) | בונים מבנה חדש או משנים את המבנה, או משלבים שתי פעולות | שרשרת חדשה עם כל הזוגיים; תור חדש בסדר הפוך; הוצאת כל המופעים של x ממחסנית; מיזוג שני מערכים ממוינים |
| **קשה** (`hard`) | ברמת שאלת בגרות: כמה סעיפים שנשענים זה על זה, מבנה בתוך מבנה, מחלקה + פעולה חיצונית, ניתוח סיבוכיות | שאלות בגרות מלאות |

## הניסוח

כמו בבגרות: "כתוב פעולה ששמה ..., המקבלת ... ומחזירה ...", דוגמה עם התוצאה, ולמבנים — "בסיום הפעולה ... צריך להיות כמו בהתחלה" כשצריך.
לכל שאלה: נוסח (`question`), ציורים של המבנים (`figures`), והתרגיל (`exercise`) — פעולה לכל סעיף עם הצעה לפתרון, `mainCode` שמריץ את כל הסעיפים ומדפיס,
ו-`expectedOutput` — בדיוק מה ש-main מדפיס כשהכול פתור (הבדיקה מריצה ומשווה).

## main שבודק את התשובות (בשאלות הבינוניות)

ב-main יש כמה בדיקות לכל סעיף, וכל בדיקה מדפיסה שורה: `סעיף א, בדיקה 1: נכון`, או `לא נכון — התקבל ..., צריך להתקבל ...`.
הבדיקה נעשית בפעולה `check` (ב-C#: `Check`) שנמצאת בקובץ תחת "נתון בתרגיל — אין צורך לשנות"; היא משווה את הטקסט של התוצאה
(מספר, true / false, מחרוזת, מחסנית `[4,8,2]`, תור, שרשרת `4 -> 8 -> null`, מערך `[1, 2, 3]`) לטקסט הנכון.
כשהכול פתור — כל השורות "נכון", וזה גם הפלט הרצוי (`expectedOutput`).

## דוגמאות בנוסח — מימין לשמאל (חובה בכל שאלה חדשה)

הנוסח מוצג בחלונות מימין לשמאל, ומספרים, פסיקים, סוגריים ואנגלית שמעורבבים במשפט מתבלגנים בקלות (רשימה שנשברת באמצע שורה,
סוגריים שקופצים לצד השני, נקודה שהופכת "25." ל-".25"). לכן:

- **כל דוגמה בשורה משלה**: `\nלדוגמה:` ואחריו שורה לכל עובדה.
- **מצב של תור / מחסנית / שרשרת "לפני ואחרי" — בציור** (`figures` של הסעיף), לא כרשימת מספרים בטקסט. בטקסט כותבים
  "עבור התור שבציור הראשון ... התור ייראה כמו בציור השני", ובכיתוב של כל ציור — מה הוא ומה בראש: `"התור q לפני הפעולה (4 בראש)"`.
  בציור הראש תמיד באותו צד, כך שאין שאלה "מאיזה צד קוראים".
- **רשימת ערכים בטקסט — רק בסוף שורה, אחרי נקודתיים**: `המחלקים של n: 1, 2, 3, 4, 6, 12`, או שורה שכולה ערכים
  (`{9, 4, 7, 1}`, `a = {1, 3, 5, 8}`, נוסחה). לא באמצע משפט, ולא עם סוגריים צמודים אחריה (`9, 4, 6 (9 בראש)` — אסור).
- **בלי נקודה אחרי מספר בסוף שורה** (`הפעולה תחזיר 25`, לא `25.`).
- זוג בסוגריים (`(1, 2)`) ומחרוזת בגרשיים (`"abc"`) מוצגים תמיד כיחידה אחת משמאל לימין — אפשר גם באמצע משפט.

`tools/test/bank-check.sh` בודק את זה: רשימה באמצע משפט או נקודה אחרי מספר בסוף שורה — השאלה לא עוברת.
בחלונות (RtlDialog.segments ב-Visual Studio / IntelliJ, RtlText.markCode ב-Eclipse) רשימות, זוגות, חשבון ומחרוזות בגרשיים
מוצגים כיחידה אחת משמאל לימין בלי שבירת שורה באמצע, ומקף אחרי אות (`ל-other`) לא נשבר משורה לשורה.

## סעיף אחרי סעיף ("הכן סעיף ב")

כשיוצרים תרגיל מהמאגר נכנסים לקוד רק הפעולה של סעיף א, הבדיקות שלו ב-main והשורות שלו בפלט הרצוי. בחלון "השאלה" לסעיף הבא יש
כפתור "הכן סעיף ב": הפעולה של הסעיף נכנסת אחרי הפעולה של הסעיף הקודם באותה מחלקה, והבדיקות שלו — בסוף main (BankSections — לפי
מבנה הקוד, לא לפי הסמן). לכן ב-main **כל שורת הדפסה מתחילה ב"סעיף X"** (כמו `"סעיף ב, בדיקה 1: "`), ושורות ההכנה של סעיף
באות לפני ההדפסה שלו — כך החלוקה של main לפי סעיפים מדויקת. שורות בלי סעיף אחרי ההדפסה האחרונה (למשל "המחסנית אחרי:")
שייכות לסעיף האחרון. `tools/test/bank/BankSectionsCheck.java` בודק כל שאלה (Java ו-C#): סעיף א לבד, ואחרי "הכן סעיף ב" — כל הפלט.
