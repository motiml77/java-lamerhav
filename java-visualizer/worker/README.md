# השרת של "שליחת תרגיל" (Cloudflare Worker)

הכפתור **שליחת תרגיל** ב-Eclipse שולח את דף התרגיל (PDF, Word או תמונות) לשרת הקטן הזה, והשרת שולח אותו ל-Gemini —
עם ההנחיות וממשק הספרייה — ומחזיר תיאור מסודר של התרגיל (JSON בתבנית קבועה). (ב-Eclipse תמיד Java; השרת והמחולל יודעים גם C#,
בשביל כלי עתידי ל-Visual Studio.)
מהתיאור התוסף בונה את הקוד: מחלקות, `main`, ופעולה לכל סעיף עם הערה "כאן כותבים את הפתרון" — והסמן מחכה שם.

```
Eclipse (התלמיד)  ──קבצים──▶  השרת הזה (Cloudflare)  ──+ ההנחיות + המפתח──▶  Gemini
                  ◀──JSON──                         ◀──────────JSON─────────
```

## למה צריך שרת באמצע

- **המפתח של Gemini נשאר אצלכם.** הוא נשמר רק כאן, כסוד של השרת — הוא לא נמצא בתוסף, ולא מגיע למחשבים של התלמידים.
- **אי אפשר להשתמש בשרת לדברים אחרים.** ההנחיות למודל והתבנית של התשובה קבועות כאן (`src/prompt.js`); התוסף שולח רק קבצים,
  והתשובה חייבת להתאים לתבנית של תרגיל.
- **הגבלות:** רק PDF / PNG / JPG / WEBP (נבדק גם לפי תוכן הקובץ, לא רק לפי הסיומת), עד 10 קבצים ו-14MB,
  עד 6 שליחות בדקה מכל מחשב, ואפשר להוסיף מכסה יומית ומפתח-אפליקציה (למטה).
- **אפשר לשנות בלי להתקין מחדש:** את ההנחיות ואת המודל משנים כאן, ו-`deploy` — התלמידים לא צריכים לעדכן כלום.

## התקנה (פעם אחת, בערך 10 דקות, בחינם)

צריך: מחשב עם [Node.js](https://nodejs.org) (גרסה 18 ומעלה), חשבון Google וחשבון Cloudflare (חינמי).

1. **מפתח ל-Gemini:** נכנסים ל-[Google AI Studio](https://aistudio.google.com/apikey) → **Create API key**. מעתיקים את המפתח.
   (בחינם, בלי כרטיס אשראי.)
2. **חשבון Cloudflare:** נרשמים ב-[dash.cloudflare.com](https://dash.cloudflare.com/sign-up) (חינם).
3. בתיקייה הזאת (`java-visualizer/worker`) פותחים חלון פקודות (cmd / Terminal) ומריצים:
   ```sh
   npx wrangler@4 login
   npx wrangler@4 secret put GEMINI_API_KEY
   ```
   בפקודה השנייה מדביקים את המפתח מסעיף 1.
4. מעלים את השרת:
   ```sh
   npx wrangler@4 deploy
   ```
   בסוף מופיעה הכתובת שלו, למשל `https://dsviz-exercise.שם-שלכם.workers.dev`.
5. בודקים שהוא עובד: פותחים בדפדפן את `<הכתובת>/v1/health` — צריך להופיע `"ok":true`.
6. **מחברים את התוסף:** כותבים את הכתובת בקובץ `eclipse-plugin/ai.properties` (בשורה `url=`) ובונים מחדש
   (`sh tools/build-all.sh`) — או שולחים לי את הכתובת ואעדכן ואבנה את ההתקנה.

## הגדרות (לא חובה)

| מה | איך |
|---|---|
| **המודל** | ב-`wrangler.toml`, `MODELS`: רשימה לפי הסדר. ברירת המחדל: `gemini-flash-latest` (תמיד ה-Flash החדש ביותר — החזק ביותר שיש לו מכסה חינמית גדולה), ואם נגמרה לו המכסה — `gemini-flash-lite-latest` (מכסה יומית גדולה יותר). את המכסות המדויקות של הפרויקט שלכם רואים ב-AI Studio → Usage / Rate limits. |
| **מפתח-אפליקציה** | `npx wrangler@4 secret put APP_KEY` עם מילה סודית, ואותה מילה ב-`eclipse-plugin/ai.properties` בשורה `key=`. מונע שליחות מכל מי שלא משתמש בתוסף (הגנה בסיסית — המפתח נמצא בתוך התוסף). |
| **מכסה יומית לכל מחשב** | יוצרים KV: `npx wrangler@4 kv namespace create USAGE`, מעתיקים את ה-id ל-`wrangler.toml` (יש שם דוגמה) ומגדירים `DAILY_LIMIT` (ברירת מחדל 40). |
| **הגבלת קצב** | כבר מוגדרת ב-`wrangler.toml` (`LIMITER`: עד 6 בדקה מכל כתובת IP). |
| **מונה הורדות** | יוצרים KV: `npx wrangler@4 kv namespace create STATS`, מעתיקים את ה-id ל-`wrangler.toml` (יש שם דוגמה) ומעלים מחדש (`npx wrangler@4 deploy`). כפתורי ההורדה באתר מורידים ישירות מ-GitHub (עובדים תמיד, גם בלי השרת), ובמקביל שולחים לשרת `POST /v1/count/windows` (או `zip`) שמוסיף 1. האתר מציג את המספר מ-`/v1/stats`. יש גם `/dl/windows` ו-`/dl/zip` שסופרים ומפנים לקובץ. הורדות מהקישור המקוצר לא נספרות. |
| **שאלת בגרות מהאתר** | האתר שולח ל-`/v1/site/exercise` — מותר רק מהכתובות שב-`SITE_ORIGINS` (ברירת מחדל `https://motiml77.github.io`), בלי מפתח-אפליקציה, ועם מכסה יומית נפרדת `SITE_DAILY_LIMIT` (ברירת מחדל 8, נספרת רק כש-USAGE מוגדר). |

## נעילה לתשלום של התצוגה הוויזואלית (כבויה)

כרגע הקוד בתוכנה כבוי לגמרי (`License.ENABLED = false`): התוכנה לא פונה לשרת והכול פתוח. כשמפעילים אותו (משנים ל-`true`, בונים מחדש, והעדכון האוטומטי מביא לכולם), התוכנה שואלת את השרת (`POST /v1/license`) לפני שהחלון הוויזואלי נפתח. כל עוד `PAYWALL` לא מוגדר ל-`on`, התשובה היא "פתוח" לכולם, וזה המצב היום. הנעילה חוסמת רק את החלון הוויזואלי. Eclipse, תרגיל חדש, שליחת תרגיל וההרצה הרגילה ממשיכים לעבוד, והתוכנית רצה והפלט מופיע בקונסול.

כדי להפעיל את הנעילה:

1. סוד לחתימת קודי רישיון (פעם אחת, שומרים אותו גם אצלכם): `npx wrangler secret put LICENSE_SECRET`
2. ב-`wrangler.toml`, בתוך `[vars]`:
   ```toml
   PAYWALL = "on"
   PAY_URL = "https://...עמוד התשלום..."
   PAYWALL_MESSAGE = "התצוגה הוויזואלית דורשת רישיון..."   # לא חובה
   ```
3. `npx wrangler deploy`

קוד רישיון לתלמיד ששילם: `LICENSE_SECRET=<הסוד> node tools/license.mjs <מזהה, למשל מספר קבלה או מייל>`. יוצא קוד כמו `DSV-12345-1a2b3c4d5e6f7a8b`, והתלמיד מזין אותו בחלון שנפתח ("הזנת קוד רישיון").

- **ביטול קוד:** מוסיפים את המזהה ל-`REVOKED = "12345,dana@x.com"` (ב-`[vars]`) ומפרסמים מחדש.
- **כיבוי הנעילה:** מוחקים את `PAYWALL` (או משנים לערך אחר) ומפרסמים מחדש.
- **בלי אינטרנט:** התוכנה משתמשת בתשובה האחרונה שקיבלה, עד 14 יום. אם אין תשובה כזו, החלון פתוח, כדי לא לחסום תלמידים בטעות.

## חשוב לדעת

- **פרטיות:** במכסה החינמית, Google רשאית להשתמש בתוכן שנשלח לשיפור המוצרים שלה. לכן בחלון כתוב לתלמידים לא לשלוח דפים
  עם פרטים אישיים. אם רוצים שהתוכן לא ישמש את Google — מפעילים חיוב (Billing) בפרויקט ב-AI Studio.
- **מכסות:** Google משנה מדי פעם את המכסות החינמיות ואת המודלים. אם מופיעה לתלמידים ההודעה "הגענו למכסה של Gemini",
  אפשר לחכות (המכסה היומית מתאפסת בחצות שעון קליפורניה, כ-10:00 בבוקר בישראל), או לשנות את `MODELS`.
- **עלות:** Cloudflare Workers בחינם עד 100,000 בקשות ביום; Gemini — בחינם בגבולות המכסה.

## איך זה בנוי

| קובץ | מה יש בו |
|---|---|
| `src/index.js` | השרת: קבלת הקבצים, בדיקות, הגבלות, שליחה ל-Gemini (עם מעבר למודל הבא אם יש עומס), ובדיקת התשובה |
| `src/prompt.js` | ההנחיות למודל (ב-Java וב-C#), תיאור הספרייה (`unit4.collectionsLib` / `Unit4.CollectionsLib`), והתבנית (schema) של התשובה |
| `wrangler.toml` | ההגדרות של Cloudflare (שם, מודלים, הגבלת קצב) |
| `test/worker-test.mjs` | בדיקות (בלי רשת, עם Gemini מדומה): `node test/worker-test.mjs` |

נקודות הקצה:

- `POST /v1/exercise` — `multipart/form-data`: שדה `meta` (JSON: השפה — `java` או `csharp`, הערה, טקסט מקובצי Word, שמות הקבצים) ושדות `file`.
  `meta` יכול להגיע כמחרוזת (התוספים) או כ-Blob (האתר) — השרת קורא את שניהם. `meta` גדול מדי נדחה (413, "הטקסט ארוך מדי"),
  ולא "נעלם" בשקט.
  - **סדר העמודים:** התמונות / צילומי המסך לא תמיד מצורפים לפי הסדר של התרגיל. לכן כל חלק ממוספר בבקשה ל-Gemini
    (`[קובץ 2 מתוך 4: שם]`, גם הטקסט מה-Word), לפני הקבצים יש אזהרה על כך, ואחרי כל החלקים (לפני ההערה של התלמיד) — תזכורת קצרה
    (כשיש חלק אחד בלבד — בלי אזהרה ובלי תזכורת). ההנחיות מבקשות לקבוע **קודם** את סדר הקריאה מתוך מה שכתוב בחלקים (מספרי עמודים,
    `- 3 -` ו-`/המשך בעמוד 4/` בדפי בגרות, מספור הסעיפים, משפט או קוד שממשיכים מתמונה לתמונה, "המשך") — ולא לפי מספרי החלקים
    או שמות הקבצים ("צילום מסך 2" הוא רק סדר ההדבקה). תמונות מתוך קובץ Word (`X (1)`, `X (2)`) שייכות לתוך הטקסט שלו.
    בתבנית, מיד אחרי `isExercise` / `problem`: `pageNotes` (שורה לכל חלק: במה הוא מתחיל ובמה נגמר) ואחריו `readingOrder`
    (מספרי החלקים לפי סדר הקריאה) — כך המודל "חושב בקול" לפני שהוא מתחייב על הסדר (חשוב במודל הגיבוי, שלא חושב לפני התשובה),
    ורק אחר כך כותב את הסעיפים. שני השדות נשארים ב-`exercise` שבתשובה (`pageNotes` עד 1500 תווים): הלקוחות (Eclipse, VS Code,
    Visual Studio, האתר) מתעלמים מהם; הם עוזרים לבדוק תקלות, וחוזרים למודל כמו שהם בבקשת תיקון.
  - **מחלקות:** בתשובה צריכה להופיע כל מחלקה שהקוד צריך מלבד המחלקה הראשית והספרייה — מחלקה שהתרגיל נותן, מחלקה שהתלמיד
    מתבקש לכתוב ("כתבו את המחלקה...") ומחלקה שנובעת מהנתונים — עם התכונות שכתובות בתרגיל (בלי להמציא תכונות). גם כשסעיף מבקש
    רק את כותרת המחלקה והתכונות — התכונות נכתבות, והסעיף עובר ל"שאלות בלי קוד". אם בכל זאת סעיף שייך למחלקה שלא תוארה, או שהמחלקה
    הגיעה ריקה (`public class Book { }`), התוסף והאתר יוצרים אותה עם ההערה "הוסיפו כאן את התכונות שמתוארות בתרגיל".
  - `maxOutputTokens` הוא 65536 (המקסימום של מודלי Flash): המחשבה של המודל והתשובה חולקות את המכסה, ובתרגיל ארוך עם הרבה תמונות 32K עלולים
    לא להספיק. תשובה שנחתכה בכל זאת נרשמת בלוג בנפרד (`gemini MAX_TOKENS <model>`), ועוברים למודל הבא.
- `POST /v1/repair` — כשהקוד שנבנה לא התקמפל: התוסף שולח את הקוד ואת השגיאות, ומקבל תיאור מתוקן (פעם אחת לכל תרגיל).
  עם `"mode": "solution"` — כשההצעה לפתרון (`tasks[].solution`) לא נתנה את הפלט הצפוי: התוסף שולח את הקבצים עם ההצעות ואת
  מה שקרה (הפלט בפועל מול `expectedOutput`, או שגיאות), ו-Gemini מתקן את ההצעה — או את `expectedOutput` אם הוא השגוי.
- `GET /v1/health`.

הבקשה ל-Gemini נבנית בשרשור מחרוזות, בלי `JSON.parse`/`JSON.stringify` על הקבצים עצמם (זה איטי מאוד בקבצים גדולים, ול-Worker
החינמי יש מגבלה של 10 מילישניות זמן מעבד לבקשה). ה-base64 נוצר בקוד מקומי (`Buffer`, דרך `nodejs_compat`).
