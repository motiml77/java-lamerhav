# מאגר השאלות: מודלים חישוביים

כל שאלה היא קובץ JSON בתיקייה של הנושא שלה: `dfa/` (אס"ד), `nfa/` (אסל"ד), `pda/` (אוטומט מחסנית), `tm/` (מכונת טיורינג).
הנושאים, הסדר שלהם והשמות: `topics.json`.

הכלי נפתח מ-`file://`, ושם אי אפשר לקרוא קבצי JSON. לכן אחרי כל שינוי בונים את הקובץ שהדף טוען, ומריצים את הבדיקות:

```
cd app
node tools/bank-build.js     # bank/**/*.json  ->  app/js/bank/data.js
node --test                  # כולל test/bank.test.js
```

`test/bank.test.js` נכשל אם `data.js` לא מעודכן, אם שאלה לא נקראת, אם דוגמה לא מתאימה לשפה, או אם הפתרון השמור לא מקבל בדיוק את השפה.

## רמות קושי

| רמה | מה זה | דוגמאות |
|---|---|---|
| **קל** (`easy`) | תנאי אחד: ספירה, סוף או התחלה, אורך | מספר זוגי של a; מילים שמסתיימות ב-b; aⁿbⁿ |
| **בינוני** (`medium`) | רצף, איסור, שילוב של שני תנאים, מכונה שמחשבת | מכילה aba; בלי שתי אותיות זהות ברצף; הוספת 1 למספר בינארי |
| **קשה** (`hard`) | ברמת בגרות: כמה סעיפים שנשענים זה על זה, מכפלה של אוטומטים, הסבר | חיתוך של שתי שפות; מאסל"ד לאס"ד; wwᴿ עם הסבר |

בכל נושא השאלות מסודרות מקל לקשה (`order` בתוך הרמה). בכל נושא לפחות 8 שאלות.

## המבנה של קובץ

```json
{
  "id": "dfa-even-a", "topic": "dfa", "level": "easy", "order": 1,
  "title": "מספר זוגי של a",
  "alphabet": ["a", "b"],
  "question": {
    "intro": "נתון הא\"ב Σ = {a, b}.",
    "sections": [
      { "label": "א", "kind": "build", "machine": "dfa",
        "language": "w ∈ {a,b}* | #a(w) זוגי",
        "text": "בנו אס\"ד המקבל ...", "hint": "...",
        "examples": { "in": ["", "aa", "bb", "abba"], "out": ["a", "ab", "aaab"] },
        "reference": { "states": [["q0", 120, 160, "A"], ["q1", 320, 160, ""]],
                       "edges": [["q0", "q1", "a"], ["q1", "q0", "a"], ["q0", "q0", "b"], ["q1", "q1", "b"]] } },
      { "label": "ב", "kind": "words", "language": "w ∈ {a,b}* | #a(w) זוגי", "text": "רשמו שלוש מילים ...", "hint": "..." }
    ]
  }
}
```

- `id` כמו שם הקובץ, ו-`topic` כמו שם התיקייה (`bank-build.js` בודק).
- `language`: אותו כתיב כמו בלשונית "שפה" (ראו `docs/SPEC.md`). בשאלה היא מוצגת בתצוגה היפה, ובתרגיל היא נעולה בפס שמעל הקנבס.
- `examples.in` / `examples.out`: מילים בשפה ומחוצה לה. מחרוזת ריקה היא ε.

## סוגי סעיפים

| `kind` | מה עושים | איך בודקים |
|---|---|---|
| `build` | בונים מכונה מסוג `machine` (`dfa`, `nfa`, `pda`, `tm`) לשפה `language` | המנוע של לשונית "שפה": הוכחה לאס"ד ולאסל"ד כשהשפה רגולרית, אחרת כל המילים הקצרות |
| `tm-output` | מכונת טיורינג שמחשבת: עוצרת במצב מקבל, ועל הסרט נשאר הפלט | הדוגמאות שב-`cases`, ועוד כל הקלטים ב-`domain` עד אורך 7. `rule` הוא שם הכלל ב-`core.js` (`complement`, `unary-add`, `binary-inc`) |
| `words` | רושמים 3 מילים בשפה ו-3 מחוצה לה | כל מילה מול השפה, בלי כפילויות, רק אותיות מהא"ב |
| `explain` | הסבר במילים (למשל למה השפה לא רגולרית) | אין בדיקה אוטומטית: `answer` היא תשובה לדוגמה (💡), והתלמיד מסמן שסיים |

סעיף `build` או `tm-output` צריך פתרון (`reference`): `states` הם `[שם, x, y, דגלים, זווית לולאה]` (`"A"` למצב מקבל, המצב הראשון
הוא ההתחלתי), ו-`edges` הם `[מ, אל, תווית]` בכתיב של תוויות הקשת בכלי (`a`, `a, b`, `a, Z/AZ`, `a/b, R`). `blank` למכונת טיורינג (ברירת מחדל `_`).
הבדיקה משווה כל פתרון לשפה: לאס"ד ולאסל"ד בהוכחה מלאה, ולאוטומט מחסנית ולמכונת טיורינג בכל המילים הקצרות.

## הנוסח

כמו בבגרות: "בנו אס"ד המקבל את השפה ...", "רשמו שלוש מילים ...", "הסבירו מדוע ...". למכונת טיורינג שמחשבת אומרים בדיוק מה הקלט
(`הקלט הוא מספר בבסיס 2`), מה נשאר על הסרט, ושהמכונה עוצרת במצב מקבל.

## מימין לשמאל (חובה בכל שאלה חדשה)

הנוסח מוצג מימין לשמאל, ואותיות לטיניות, מספרים, סוגריים ונוסחאות שמעורבבים במשפט מתבלגנים בקלות. לכן:

- **כל דוגמה בשורה משלה**: `\nלדוגמה:` ואחריו שורה לכל עובדה (`עבור 1011 הפלט יהיה 1100`).
- **נוסחה או קבוצה בסוף שורה, אחרי נקודתיים**, או בשדה `language` (שם היא מוצגת בתיבה משלה, משמאל לימין).
- **בלי נקודה אחרי מספר או אות בסוף שורה** (`ל-1`, לא `ל-1.`).
- **בלי קו מפריד ארוך ובלי סימן קריאה.**
- מילה בגרשיים (`"aab"`), קבוצה (`{a, b}`) וביטוי (`n ≥ 2`) מוצגים כיחידה אחת משמאל לימין, גם באמצע משפט.

`test/bank.test.js` בודק את שלושת הכללים האחרונים. בחלון, `BankView.rtl` (ב-`js/bank/window.js`) עוטף כל קטע לטיני או מתמטי
ב-`<bdi dir="ltr">`, כמו RtlText בתוכנות של Java.

## סעיף אחרי סעיף ("הכן סעיף ב'")

"צור תרגיל" פותח את הסעיף הראשון שבונים בו מכונה: מכונה ריקה מהסוג הנכון, עם הא"ב של השאלה. בחלון "השאלה" לסעיף הבא שבונים בו
מכונה יש "הכן סעיף ב'": המכונה של הסעיף הקודם נשמרת, ועל הקנבס נפתחת מכונה חדשה לסעיף. "לסעיף א'" מחזיר אליה. סעיפי `words`
ו-`explain` נעשים בתוך החלון עצמו.
