# gemini-proxy — קובץ חלופי מלא

## למה זה כאן

בדקתי ישירות מול `gemini-proxy.motiml77.workers.dev` (ה-Worker שכל בדיקות ה-AI
באתר עוברות דרכו) ומצאתי שתי תקלות:

1. **`gradeExam` ו-`checkHomework` נכשלים תמיד** — `"כל המודלים נכשלו"`.
2. **`chat` נכשל תמיד** — `"Invalid action"`, כאילו הפעולה מעולם לא נתמכה.
   זו הפעולה שמפעילה גם את כפתור "הרצה" בעמוד הלמידה וגם את עוזרת ה-AI.

**אין לי גישה לקוד המקור של ה-Worker הזה או לחשבון ה-Cloudflare שמריץ אותו** —
הוא לא בריפו הזה בכלל. הקובץ `gemini-proxy.js` כאן הוא **תחליף מלא**, כתוב
מאפס, לא עריכה של הקיים.

**אם יש לך את קוד ה-Worker הנוכחי במקום אחר** (מחשב אחר, ריפו נפרד, או
בעריכה ישירה בלוח הבקרה של Cloudflare) — שלחי לי אותו ואמזג את השיפורים
לתוכו במקום להחליף אותו לגמרי. יכול להיות שיש בו לוגיקה נוספת (תיעוד,
הגבלת קצב, התאמות לבתי ספר) שלא ידועה לי ושכדאי לשמר.

## מה תוקן

- **המודל**: `gemini-3.7-flash` (הכי עדכני שעדיין חינמי לגמרי, בלי כרטיס
  אשראי), עם נפילה חזרה ל-`gemini-2.5-flash` ואז `gemini-2.0-flash` אם
  הראשון לא זמין רגעית — כדי שתקלה במודל אחד לא תפיל את כל הבדיקה.
- **`action: 'chat'` נוסף** — משרת גם את "הרצה" בעמוד הלמידה (מדמה מהדר,
  טמפרטורה 0, מחזיר רק פלט גולמי) וגם את עוזרת ה-AI (מדריכה, לא פותרת
  במקום התלמידה — עם ההקשר של השאלה מוזרק לפרומפט).
- **הפרומפטים המפורטים לא שוכתבו.** `BASE_SYSTEM_PROMPT`,
  `DEFAULT_GRADING_PROMPT`, `DEFAULT_HOMEWORK_PROMPT` ו-`DEFAULT_AUTOMATA_PROMPT`
  (ב-`app.html`, סביב שורה 560) כבר בנויים היטב ונשלחים מוכנים מהלקוח.
  ה-Worker רק מעביר אותם ל-Gemini ומפרש את התשובה — לא בונה מחדש.
  הפרומפט היחיד שנכתב כאן מאפס הוא זה של `chat`, כי ללקוח אין גרסה משלו.
- **פענוח JSON סלחני** — Gemini לפעמים עוטף JSON בגדר markdown למרות
  `responseMimeType: application/json`; מנוקה לפני הפענוח.
- **ניקוד מוגבל למקסימום השאלה** — הגנה מפני מודל שמחזיר ציון גבוה מדי.
- **CORS מפורש** — כל דומייני הפרויקט (חי, דמו, תצוגות מקדימות, כולל
  תת-דומייני preview של Vercel) ו-`localhost` לפיתוח.

## שינוי נלווה ב-app.html

הוספתי `questionPoints` לבקשת `gradeExam` (בדיוק כמו שכבר קיים ב-
`checkHomework`) — בלעדיו ה-Worker לא ידע את הניקוד המקסימלי של שאלת
מבחן ויצטרך לנחש. זה כבר בענף `manager`, לא צריך לעשות כלום נוסף.

## מה נבדק, ומה לא

**נבדק** (`node test-worker.mjs` מהתיקייה הזו, 32/32): מיפוי השדות בשתי
פעולות הבדיקה, פענוח JSON עטוף ב-markdown, שרשרת הנפילה בין מודלים
(גם הצלחה בניסיון שני וגם כישלון מוחלט), חיתוך ניקוד למקסימום, שני
המצבים של `chat` (כולל מיפוי `assistant`→`model` בהיסטוריית השיחה), דחיית
action לא מוכר, CORS (כולל דחיית מקור לא מורשה), חוסר מפתח API, ותמונה
מוטמעת.

**לא נבדק — לא יכולתי:** קריאה אמיתית ל-Gemini. אין לי כאן מפתח API,
ואין לי גישה לפרוס ל-Cloudflare ולבדוק מקצה לקצה. כל הבדיקות רצות מול
`fetch` מדומה. **חובה לבדוק ידנית אחרי הפריסה** — סעיף "בדיקה" למטה.

## פריסה

### קודם — מפתח Gemini API (אם עדיין אין, או אם קיים אבל פג/הוגבל)

1. https://aistudio.google.com/apikey → **Create API key** → לבחור פרויקט
   קיים או ליצור חדש. **לא צריך כרטיס אשראי** — זה מפתח לשכבה החינמית.
2. להעתיק את המפתח (`AIza...`).

### אפשרות א' — Wrangler CLI (מומלץ, אם ה-Worker נוצר ככה במקור)

```bash
cd worker
npm install -g wrangler   # אם עדיין אין
wrangler login
wrangler secret put GEMINI_API_KEY
# מדביקים את המפתח כשמבקש, Enter
wrangler deploy
```

`wrangler deploy` עם `name = "gemini-proxy"` (כבר מוגדר ב-`wrangler.toml`)
מעדכן את ה-Worker הקיים באותה כתובת בדיוק — `gemini-proxy.motiml77.workers.dev`
לא משתנה.

### אפשרות ב' — לוח הבקרה של Cloudflare (אם אין CLI מוגדר)

1. https://dash.cloudflare.com → **Workers & Pages** → למצוא את `gemini-proxy`
   הקיים (או ליצור Worker חדש באותו שם אם הוא לא מופיע).
2. לשונית **Settings → Variables and Secrets** → **Add** →
   שם `GEMINI_API_KEY`, סוג **Secret**, ולהדביק את המפתח → **Save**.
3. לשונית **Edit code** (או **Quick Edit**) → למחוק את כל התוכן הקיים →
   להדביק את כל `gemini-proxy.js` מכאן → **Deploy**.

### בדיקה — חובה אחרי הפריסה

```bash
curl -X POST https://gemini-proxy.motiml77.workers.dev \
  -H "Content-Type: application/json" \
  -d '{"school":"lamerhav","action":"chat","messages":[{"role":"user","content":"System.out.println(2+2);"}],"context":{"mode":"run-code"}}'
```

תשובה תקינה: `{"response":"4"}` (או משהו קרוב — Gemini לא תמיד מדויק
ב-100% על ריצת קוד). קוד 500 עם `"כל המודלים נכשלו"` אחרי הפריסה אומר
שהמפתח לא הוגדר נכון או שהוא לא תקין — לבדוק את שלב הגדרת ה-secret.

אחר כך לבדוק בפועל באתר עצמו: לפתוח שיעור עם דוגמת קוד ולחיצה על
"הרצה", ולוודא שמורה יכולה לבדוק תשובת מבחן עם AI.
